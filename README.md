# Алгоритми — лабораторні та уроки

```
Алгоритми/
├── Lessons/     уроки: lesson_1.cpp, lesson_2.cpp, ...
├── Lab/
│   ├── Lab-1/   lab-1.cpp ... lab-7.cpp
│   └── Lab-2/   lab-1.cpp ...
└── build/       зібрані програми (у Git не потрапляють)
```

## Збірка й запуск

Найпростіше: скрипт `run` у корені теки. Він сам обирає ім'я програми
(`Lab/Lab-2/lab-2.cpp` → `build/lab-2/lab-2`, `Lessons/lesson_8.cpp` → `build/les_8`),
створює підтеку в `build/`, збирає і одразу запускає.

```bash
cd "/Users/ander1.sage/Desktop/Алгоритми"
./run Lab/Lab-2/lab-2.cpp        # зібрати й запустити
./run -b Lab/Lab-2/lab-2.cpp     # лише зібрати
./run Lessons/lesson_8.cpp
```

Вручну (те саме, що робить скрипт):

```bash
mkdir -p build/lab-2
clang++ -std=c++23 -Wall -Wextra -Wpedantic -g -fsanitize=address,undefined \
        -o build/lab-2/lab-2  Lab/Lab-2/lab-2.cpp
./build/lab-2/lab-2
```

Важливо: після `-o` пишеться ім'я **програми без `.cpp`**. Якщо написати
`-o build/lab-2/lab-2.cpp`, clang створить програму з іменем `lab-2.cpp`, і в
`build/` з'явиться файл, схожий на вихідник, але це не він.

Теки `*.dSYM` поруч із програмою з'являються через `-g` при збірці за один
крок. Вони не шкодять (це дані для відлагоджувача), їх можна видаляти. Скрипт
`run` збирає у два кроки (спершу `.o`, потім лінкування), тому їх не створює.

Якщо компілятор вивів помилки, читай **першу** з них, решта зазвичай є наслідком.

| Прапорець | Що робить |
|---|---|
| `-std=c++23` | версія стандарту |
| `-Wall -Wextra -Wpedantic` | попередження. Стався до них як до помилок |
| `-g` | номери рядків у звітах санітайзерів і в lldb |
| `-fsanitize=address,undefined` | ловить вихід за межі, використання після звільнення, переповнення |
| `-c` | лише скомпілювати в `.o`, без лінкування |
| `-o build/...` | куди покласти результат |

Якщо санітайзер знайшов помилку під час запуску, шукай у звіті рядок виду
`#0 ... in main lab-1.cpp:РЯДОК` — це місце помилки, решта є шумом.

При ручній збірці тека `build/lab-N` має існувати, інакше буде
`cannot open output file`: `mkdir -p build/lab-3`. Скрипт `run` створює її сам.
